The original route used one visual-encoder invocation per prefix; the proposed route uses five. That changes those prefix forwards from 1,024 to 5,120, adding 4,096 visual-encoder invocations with no extra image frames. Corresponding observation/proprioception invocation changes must be recorded against the actual implementation; under the proposed one-encode_obs-per-image caller they likewise rise from 1,024 to 5,120 for these prefixes alone.

The proposed new 88-frame gate likewise has 88 actual pointwise visual calls; these are not a second addition to the same encoded-frame counts. An original single batch-16 RGB encoding and a conditional canonical supplier with no encoder forward are not the same baseline. Do not assume their counts are interchangeable or add the same reference twice.
