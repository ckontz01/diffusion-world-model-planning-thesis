## Decision and scientific scope

Propose a separately named DINO representation-control amendment, A2 RC1, rather than relabel the failed A2 gate as passed. Define one image-to-feature procedure for every DINO role, refit its two readouts using the original fit-only roots and unchanged ridge recipe, and require new independent acceptance before any continuation. Preserve the original A2 lineage and all accepted and failed artifacts.

The proposed visual procedure is pointwise execution at batch one with the existing BF16 autocast, not a new precision or backend. Its structural justification is that the experimental unit is one RGB observation: its features should not depend on the other images assembled with it by a role-specific caller. This is a post-observation amendment, not a predeclared design. Batch one is proposed to define that pointwise map and preserve the existing source/goal/planner path, not because it agreed with batches five/eight or improved efficacy. It did not agree with those batches. No efficacy or readout predictions have been inspected, and no alternative procedure is being selected by a performance or agreement search.

The decision concerns the DINO representation only. Le-WM remains at its previously accepted scope; this amendment does not certify unmeasured arbitrary batch invariance for Le-WM or authorize changing its representation. Review must explicitly assess whether that bounded scope supports the intended within-backbone diagnostic claims. Cross-backbone scores are never pooled as if their representations were identical.

## One image procedure across DINO roles

Let E pointwise of x return a float32 tensor of shape 196 by 384 from one HWC uint8 RGB image of shape 224 by 224 by 3. Use exactly the existing authenticated DINOv2 encoder bytes, pinned source, device/node/runtime, evaluation flags and transforms: CHW conversion; float32 scaling by 255; Resize224; CenterCrop224; normalization with mean and standard deviation 0.5; native Resize196; original forward_features x_norm_patchtokens; float32 visual output. The encoder executes under the existing BF16 autocast. No upcasting of model weights, TF32/backend switch, quantization or kernel search is proposed.

Any caller with N images must invoke that same encoder path N times, each with image batch one and T=1, in its existing order, and concatenate only after each image's feature extraction. A five-frame prefix therefore has five independent image forwards, not one five-image forward; an eight-image training slice has eight, not one eight-image forward. No role-dependent padding, duplicated-image context, cross-image normalization or mixed-image encoder call is allowed. Grouping image outputs into temporal features does not change their individual extraction procedure.
