## Tree, clocks and controls

Build everything before the initial action. Retain the exact baseline's first five plus last ten primitives as node 0/suffix 0. Other prefixes are exact unique first-five sequences from the final baseline proposal population in cost/index order. For each of at most four prefixes run a full N300/K30/J30 suffix-constrained solve. Retain baseline suffix first where applicable, then constrained elite mean, then final-population suffixes in cost/index order, capped at four exact unique suffixes. Missing slots stay missing; there is no proximity-based merging. A final ≤16-plan rollout supplies all prefix/terminal features and charges the previously unscored baseline mean. Hash-content decision ties are deterministic; exact baseline commitment wins ties. This is different search packaging, not a rank-only intervention on a flat bank.

All learned arms use the identical preconstructed tree, six fixed policy modes in `Selector`, and the same fitted response sampler/terminal head. Inputs, four-component model, losses, preprocessing, optimizer and fixed 128-response integration are in `TRAINING-AND-DECISION.md`. All weights remain fixed at deployment. A static selects the full plan before observing. B uses the baseline prefix. C chooses unconditional expected final native success, then its own prefix's suffix. D pays all C predecision integration but ignores the actual residual. E is a larger same-information MLP; F is the explicitly approximate Bayesian last-layer control. Exact Bayes is only available on the supplied tractable artificial laws; it is not a robotics oracle. Terminal success contributes P(S), failure zero, and active contribution P(A)E[max q]. No additional arbitrary probe penalty.

For A–F: execute five then the associated ten, never another prefix's suffix; stop at any native termination; return to the unchanged baseline at absolute action 15, replanning at 15,30,…135. No reset/restart/repeated verification. For ordinary vanilla: fresh N300/K30/J30 at 0,15,…135. Separate early-replanning comparator: the same original baseline's five-action prefix, then unrestricted full fresh N300/K30/J30 at 5,20,…140. At 140 only the remaining ten actions are executed; search still receives the complete budget. This arm may build fresh post-observation candidates and is not a fixed-tree control.

Planner RNG is keyed only by `[94041, reference_index, absolute_clock]`, never arm/outcome. Constrained search uses `[94001, prefix-content-hash32]`. Integration seed 94021 is separate and shared across comparators. Identical initial states therefore produce identical original baseline plans. Evaluation order rotates the eight-arm list by the source's frozen allocation position. One policy episode per source/arm; no seed, anchor or tail-repeat grid.
