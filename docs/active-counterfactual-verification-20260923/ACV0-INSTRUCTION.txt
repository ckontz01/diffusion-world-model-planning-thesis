WORKING QUESTION

Can a short, budgeted action prefix provide evidence that improves the
choice between its possible continuations—and can we learn which prefix
is worth executing to obtain that evidence?

The proposed contribution is the learned response-to-continuation
relationship and its practical use around a frozen planner.

Do not claim to invent dual control, Bayesian experimental design,
feedback adaptation or active sensing. Novelty and robot efficacy
remain unestablished.

3. BUILD AN EXPLICIT PREFIX–CONTINUATION TREE

For implementation, use at most four prefix slots and four continuation
slots per prefix: at most16 complete fifteen-action plans.

Include the exact action sequence the unmodified baseline would return:
its first five actions as a prefix and its remaining ten as one of that
prefix's continuations.

Define and document a deterministic, outcome-independent rule for:
- Choosing the other prefixes from available planner proposals.
- Constructing suffixes with each prefix held fixed.
- Keeping the baseline sequence unchanged.
- Handling exact duplicates and unavailable unique slots.
- Resolving score ties.

Do not pretend independently sampled continuous sequences share a prefix
merely because their first actions are approximately close.

Construct the entire matched tree using information available BEFORE
prefix execution. Do not use observed branch outcomes to choose its nodes.

The matched feedback selectors may choose only among the suffixes of
the prefix actually executed. They may not:
- Borrow a suffix that assumes a different prefix happened.
- Regenerate extra candidates after inspecting the response.
- Query the simulator for an unexecuted branch during deployment.

This is a change to search packaging, not a rank-only intervention on
an unchanged flat bank. Count every tree-construction rollout and model
call, including any needed to retain the actual baseline plan.

4. IMPLEMENT THE LEARNED JOINT RESPONSE MODEL

Implement the four-component model proposed in METHOD.md.

Available inputs:
h = pre-prefix observed history, action history, goal and remaining budget.
p = proposed five-action prefix.
a_i = a ten-action continuation associated with that prefix.
r = observed prefix latent minus its frozen-model predicted latent.

Use a shared context/prefix encoder to produce:
- Four component probabilities pi_m(h,p).
- Four diagonal-Gaussian response means and scales.

Use a shared continuation encoder to predict:
s_m(h,p,a_i) = probability of full-budget native success under component m.

After observing r:
w_m ∝ pi_m × Normal(r; mu_m, Sigma_m)
q_i(h,p,r) = sum_m w_m × s_m(h,p,a_i)

Implement stable log-domain posterior normalization, positive bounded
variance parameterization, finite-value checks and checkpoint round trips.

Fit the proposed response likelihood and candidate outcome objective
using artificial data now. Document the exact losses, reductions,
weights, parameter counts, optimizer and seeds before fitting.

Use a response-likelihood term once per actual prefix observation.
Do not count its duplication across suffix labels as extra independent
response evidence. Average outcome terms hierarchically within
source/prefix; coupled branch outcomes are not independent sources.

Fit preprocessing on fitting sources only. No reference-ID, candidate
slot-ID shortcut, true hidden parameter, future outcome or simulator-only
state unavailable to the controls may enter deployment inputs.

Before-prefix response predictions must not depend on which future
suffix happens to be evaluated. Changing the suffix bank must not
change the predicted physical response to a fixed prefix.

There are no optimizer steps at deployment. All learned weights remain
fixed; only observation-conditioned posterior weights change.

Leave Gaussian contrast compression out of the first neural treatment.
Retain it as an analytical reference. Its Gaussian sufficiency result
does not establish sufficiency for this nonlinear binary-success model.

5. IMPLEMENT THE TWO-STAGE DECISION

Before execution, estimate:

V(p) = E_r [max_i q_i(h,p,r)].

Compare this with the model's estimate for committing to the original
baseline plan without an extra decision.

Use a fixed, declared integration rule and response-sampling budget,
with separate random streams and common integration samples wherever
comparisons permit. No runtime sample-count or threshold sweep.

Choose the prefix by expected full-task outcome, not entropy, residual
magnitude, immediate distance or an arbitrary exploration bonus.

Execute only the selected prefix, observe its actual response, then
select its continuation using the posterior q_i.

Every prefix's physical consequences and consumed actions belong in
its eventual-success target. Do not add an arbitrary probe penalty
that double-counts a cost already represented in that target.

Handle prefix success and other native termination explicitly:
- Stop immediately when the environment terminates.
- Do not request an observation at action5 after earlier termination.
- Do not generate or execute fictitious suffixes.
- Do not evaluate only surviving prefixes and call that an unconditional
  value estimate.

Specify terminal-success, terminal-failure and active-prefix contributions
to V(p). Include terminal-prefix cases in the training/collection schema
without physically repeating unused suffix branches.

6. IMPLEMENT THE NECESSARY CONTROLS

Use the same tree, available inputs, training sources and physical budget
wherever the comparison is meant to isolate the mechanism.

Required mechanism controls:

A. Static commitment:
   Select a complete plan before seeing the prefix response.

B. Passive feedback:
   Use the baseline's fixed prefix, then the proposed response model
   to select a continuation.

C. Full active feedback:
   Choose the prefix by V(p), observe, and rerank continuations.

D. No response update:
   Retain the full method's pre-prefix selection computation but choose
   the suffix without conditioning on the actual response.
   Charge all computation; do not portray this as a cheaper controller.

E. Same-information ordinary predictor:
   A strong ordinary history-conditioned outcome model receiving the
   same available pre/post observations, actions, predictions and residual.
   It lacks the proposed shared mixture structure—not the evidence.

F. Established Bayesian feedback control:
   A correctly specified tractable Bayesian reference on artificial
   problems; propose a feasible ALPaCA-style/Bayesian-regression control
   for the real integration, with fidelity and assumptions explicit.

Use a shared response-sampling model and integration budget for active
comparisons where possible. Do not give the proposed method a better
prefix-value estimate merely by starving its control of inputs or samples.

Also specify ordinary vanilla-CEM replanning after five actions as a
practical early-replanning comparator. Because it may construct a fresh
post-prefix bank, label it separately from the fixed-tree controls and
account for its complete search budget.

This comparator must not be weakened merely to preserve a common-bank
claim. The mechanism must eventually add value beyond "observe sooner."

An information-gain prefix selector can remain an artificial diagnostic.
Do not expand into a large real comparator grid in this preparation.
